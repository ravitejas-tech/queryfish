# 1.0

What went into the first release, and what's planned after it. For how the pieces fit together, see
[architecture.md](../architecture.md).

The aim for 1.0 was simple: everything the README describes should actually work, and someone new should be able to get
a PR merged without needing to ask questions first.

---

## Decisions made up front

These were settled before writing the code, so they wouldn't get reopened halfway through:

| Decision    | Choice                      | Why                                                                  |
| ----------- | --------------------------- | -------------------------------------------------------------------- |
| HTTP client | User-supplied client module | No runtime dependency; auth and interceptors stay in the user's code |
| Query keys  | URL path segments           | Lets one prefix invalidate a whole resource                          |
| Pagination  | Opt-in, off by default      | OpenAPI has no pagination standard, and wrong guesses fail silently  |
| Swagger 2.0 | Supported                   | Comes for free with the Redocly loader                               |

Each of these has an [ADR](../adr/) with the full reasoning.

---

## What's in 1.0

- **Generator**: loads a spec from a path or URL, builds the IR (with recursive schemas and naming collisions handled),
  and emits types, request functions, queries, mutations, opt-in infinite queries and a barrel file.
- **CLI**: `queryfish generate` with `--config`, `--input`, `--output`, `--client`, `--dry-run`, `--watch`,
  `--no-format` and `--silent`. Flags override the config file, and it exits non-zero on failure.
- **Errors** that point at the spot in the spec:
    ```
    error: cannot resolve schema
      at paths./users.get.responses.200
      in openapi.yaml:42
    ```
- **Generated code** with a "do not edit" header, JSDoc from each operation's `summary` and `description`, and
  `@deprecated` where the spec marks it.
- **Tests**: snapshot tests for three fixtures, unit tests for naming, and compile tests that run `tsc` over the
  generated output.
- **Example app** in `examples/petstore-react/`, with its generated output committed. CI regenerates it and fails if the
  committed copy is out of date.
- **Project setup**: MIT license, contributing guide, code of conduct, issue and PR templates, CI on Node 20, 22 and 24,
  and releases through Changesets with npm provenance.

### Dependencies

Kept short on purpose: `@redocly/openapi-core` (parsing and bundling), `prettier` (formatting output), `cac` (CLI),
`chokidar` (watch mode) and `jiti` (loading TypeScript config files).

There are no peer dependencies. Generated code imports only `react-query-kit`, `@tanstack/react-query` and the user's
client module.

The package is built with [tsdown](https://tsdown.dev), which outputs ESM, CJS and type declarations.
